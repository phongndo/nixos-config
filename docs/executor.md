# Executor shared between Mac and NixOS

The Mac (`dp`, Tailscale `100.90.20.37`) is the single Executor server.
All four agents (DSH, Codex, OpenCode, Pi) are configured on both machines:

```text
Mac agent ───────────────────────────────────────────→ Mac executor mcp
Linux agent → ~/.local/bin/executor-mcp → Tailscale SSH ↗       ↓
                                                     Mac's existing daemon
```

Mac agents launch `/Applications/Executor.app/Contents/Resources/executor/executor`
with `mcp --no-artifacts --search-tools --elicitation-mode browser`. Linux
(`z@box`, `100.122.138.125`) launches the same command through restricted SSH.
Agent configs contain no Executor bearer token; the CLI reuses the Mac daemon.

This shares integrations, credentials, tool policies, and browser sessions;
there is no database or API-token copy. Browser/computer-use tools operate on
**the Mac**, not the Linux desktop. Both machines need Tailscale running, and
the Mac must be awake with SSH Remote Login and Executor available.

## Managed configuration

`chezmoi/private_dot_local/bin/executable_executor-mcp` owns the SSH options.
The wrapper uses a pinned Mac host key and a dedicated, non-interactive key;
it does not use the user's SSH config, agent forwarding, or port forwarding.
Each agent launches its own MCP transport on demand. No tunnel service or new
listening port is needed. The box's existing standalone Executor daemon is
left intact, but these agents bypass it (`executor tools integrations` on the
box still queries that independent local daemon).

`chezmoi/run_after_sync-agent-mcp.sh.tmpl` reconciles the agent entries on both hosts
after every chezmoi apply, including Home Manager activation. It invokes
`~/.local/bin/sync-agent-mcp`, which replaces only the `executor` entry and
preserves other runtime settings and MCP servers.

| Agent | Configuration on each machine |
| --- | --- |
| Pi | `~/.config/mcp/mcp.json`, read by the Pi MCP extension |
| Codex | `~/.codex/config.toml` |
| OpenCode | `~/.config/opencode/opencode.jsonc` |
| DSH | `~/.dsh/cordis.patch.yml` (all profiles) |

DSH's patch is managed directly by chezmoi. Pi's mutable `/mcp` overlay is
not overwritten; deliberately disabling Executor there survives an apply.
OpenCode's chezmoi-managed `.jsonc` is plain JSON; the reconciler fails safely
rather than stripping comments from an independently edited JSONC file.
The sync script and DSH patch apply on both platforms; only the SSH wrapper
and pinned SSH host key are Linux-only. The reconciler replaces only each
agent's Executor entry, never its model/provider settings. Pi's previous
HTTP entry has been replaced with stdio, and the matching native Codex and
OpenCode entries use the same platform-specific command.

Only DSH, Codex, OpenCode, and Pi are supported, matching the Mac's installed
agent roster. The reconciler does not create config for other agents. Their
previously generated Executor entries were removed from box; old sessions
and account stores were preserved. See [Agent installation](agents.md).

- Pinned Mac host key: `~/.ssh/executor_mac_known_hosts`, managed by chezmoi.
- Mac authorization: one entry in `/Users/dp/.ssh/authorized_keys`, restricted
  with `from="100.122.138.125",restrict` and this forced command:

  ```text
  /Applications/Executor.app/Contents/Resources/executor/executor mcp --no-artifacts --search-tools --elicitation-mode browser
  ```

The key grants MCP access to the same trusted integrations as the Mac agents,
not a general SSH shell. Browser-mode approvals remain required whenever
Executor requests them; the tunnel does not approve actions automatically.

The private key and Mac authorization are not generated by a rebuild. After
reinstalling either machine, provision a new dedicated key, authorize its
public half with the restrictions above, and verify the Mac host-key
fingerprint locally before updating the pinned key. Never commit the private
key or Executor credentials. Remove the corresponding authorized-keys line
to revoke the box's access.

## Checks and maintenance

On box:

```sh
python3 ~/.local/bin/sync-agent-mcp
mise exec -- codex mcp get executor
mise exec -- opencode --pure mcp list
mise exec -- dsh --profile headless --dump-config
```

Restart existing agent sessions after configuration changes. Pi can instead
use `/reload`, then `/mcp` to inspect its connection. If SSH reports a changed
host key, verify the actual Mac public host key rather than disabling strict
checking. If it times out, check Tailscale and whether the Mac is asleep.

Original runtime configs changed by the reconciler are backed up once under
`~/.local/state/executor-agent-config/backups/`, mirroring their home-relative
paths. Configs and backup files are atomically written with mode 0600. No
credentials are included in the chezmoi source.

Live verification passed on **both Mac and Linux**:

- Codex's native app-server `mcpServerStatus/list` discovered all eight tools.
- Pi's actual MCP config loader and connector discovered all eight tools and
  successfully called `skills`.
- OpenCode's native `mcp list` reported Executor connected.
- A temporary diagnostic plugin confirmed all eight `mcp__executor__*` tools
  in DSH's actual tool registry while its web app was running. The diagnostic
  plugin was supplied only to the test process, not installed in the profile.

The eight tools are `execute`, `skills`, `resume`, and the five search loaders
for Chrome DevTools, Chrome, Computer Use, Fastmail, and Firecrawl. These checks
did not run a model request or change model-provider credentials. Existing agent
sessions need to restart or reload to adopt new configuration.
